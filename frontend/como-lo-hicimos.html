02Arquitectura

El navegador solo habla con Nginx (puerto 80). Nginx reparte cada ruta /api/... a su microservicio. Los servicios se comunican entre sí por la red interna de Docker usando el nombre del servicio como dirección.

04ORMs: un ORM por lenguaje

Qué es

Un ORM (Object-Relational Mapper) convierte clases del lenguaje en tablas y objetos en filas, así no escribimos SQL a mano.

Cómo lo usamos

Cada servicio SQL usa el ORM de su lenguaje visto en clase, y cada uno tiene su propia base de datos dentro de Postgres.

Por qué

Las tablas se crean solas al arrancar (create_all / ddl-auto / AutoMigrate), el código queda más legible y evitamos inyección SQL.

servicio-auth-python/app/database.py — SQLAlchemy
class Usuario(Base):
    __tablename__ = "usuarios"
    id = Column(Integer, primary_key=True)
    email = Column(String(160), unique=True, nullable=False, index=True)
    password_hash = Column(String(100), nullable=False)   # nunca la clave en texto plano
    rol = Column(String(20), default="estudiante")

Base.metadata.create_all(engine)   # crea la tabla al arrancar
servicio-clases-java/.../Clase.java + ClaseRepo.java — Spring Data JPA
@Entity
public class Clase {
  @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id;
  private Integer semana;
  private String titulo;
  private String estado = "SIN_MATERIAL";  // -> PROCESANDO -> BORRADOR -> PUBLICADA
}

@Repository
public interface ClaseRepo extends JpaRepository<Clase, Long> {
  List<Clase> findAllByOrderBySemanaAscIdAsc();   // Spring genera el SQL por el nombre del metodo
}
servicio-clases-java/.../Materia.java + Seccion.java — relaciones JPA
@OneToMany(mappedBy = "materia", cascade = CascadeType.ALL, orphanRemoval = true)
private List<Seccion> secciones;          // una materia tiene muchas secciones

@ManyToOne @JoinColumn(name = "materia_id")
private Materia materia;                 // cada seccion pertenece a una materia

@ElementCollection                       // tabla seccion_estudiante

@Query("select s from Seccion s where :id member of s.estudiantes")
List<Seccion> deEstudiante(Long id);       // secciones de un estudiante

05MongoDB + Mongoose (NoSQL)

Qué es

Base de datos de documentos JSON, sin esquema rígido. Mongoose agrega modelos y validación desde Node.js.

Cómo lo usamos

El servicio de IA guarda el contenido de cada presentación y las 5 preguntas + respuestas de cada estudiante.

Por qué

Cada presentación tiene un número distinto de diapositivas y las preguntas van anidadas: un documento lo representa natural, sin tablas intermedias.

servicio-ia-node/src/modelos.js
const contenidoSchema = new mongoose.Schema({
  claseId:        { type: Number, required: true, unique: true },
  diapositivas:   [{ n: Number, titulo: String, texto: String, explicacion: String }],
  publicado:      { type: Boolean, default: false },
  preguntasUsadas: [String],   // para que ninguna pregunta se repita entre estudiantes
});

const asignacionSchema = new mongoose.Schema({
  claseId: Number, estudianteId: Number,
  preguntas: [{ texto: String, respuesta: String }],   // exactamente 5
  entregada: { type: Boolean, default: false },
});
asignacionSchema.index({ claseId: 1, estudianteId: 1 }, { unique: true });

06Docker Compose avanzado

Todo el sistema (2 bases de datos, 4 microservicios, Mailpit y Nginx) se levanta con docker compose up --build.

ConceptoCómo lo usamosPor qué
networksbackend (BDs + servicios) y frontend (gateway + servicios)Nginx no puede ver las bases de datos; solo los servicios llegan a ellas
healthcheckPostgres (pg_isready), Mongo (mongosh ping) y cada servicio (/health)Saber cuándo un contenedor está listo, no solo encendido
depends_oncondition: service_healthy en todosLos servicios esperan a su BD y el gateway espera a los 4 servicios
volumespgdata, mongodata, uploadsUsuarios, clases y presentaciones sobreviven a docker compose down
docker-compose.yml (fragmento)
  servicio-clases:               # Java + Spring Boot + JPA -> Postgres
    build: ./servicio-clases-java
    env_file: .env
    volumes:
      - uploads:/data/uploads      # las presentaciones persisten
    depends_on:
      postgres:
        condition: service_healthy # espera a que pg_isready responda
    networks: [backend, frontend]
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8080/health"]

Además los Dockerfiles de Java y Go son multi-stage: compilan con la imagen completa (Maven / Go) y copian solo el resultado a una imagen pequeña.

07Variables de entorno

Qué es

Un archivo .env con credenciales y configuración que se inyecta a cada contenedor con env_file.

Cómo lo usamos

En el repo solo está .env.example. Ahí van las claves de BD, el JWT, la API key de la IA y el SMTP.

Por qué

Nunca subimos secretos a GitHub (.env está en .gitignore) y la profesora configura el sistema sin tocar código.

# Python   DATABASE_URL = os.getenv("DATABASE_URL_AUTH")
# Node     mongoose.connect(process.env.MONGO_URL)
# Go       gorm.Open(postgres.Open(os.Getenv("DATABASE_URL_NOTIF")))
# Java     spring.datasource.url=${DATABASE_URL_CLASES}

08API Gateway con Nginx (bonus)

Qué es

Un reverse proxy: un único punto de entrada que reenvía cada petición al servicio correcto.

Cómo lo usamos

Nginx sirve el frontend en / y enruta /api/auth, /api/ia, /api/clases y /api/notificaciones.

Por qué

El frontend no conoce puertos internos, no hay problemas de CORS y se puede cambiar un servicio sin tocar el frontend.

nginx/nginx.conf (fragmento)
upstream clases_svc { server servicio-clases:8080; }

location /api/clases/ {
  proxy_pass http://clases_svc/;     # /api/clases/temas  ->  servicio-clases:8080/temas
  proxy_read_timeout 300s;           # la IA puede tardar
}

09Comunicación entre microservicios

Las llamadas internas viajan por la red de Docker (http://servicio-ia:3000, etc.) y se autentican con el header X-Internal-Token definido en el .env. Ejemplo completo cuando la profesora sube y publica una clase:

  1. Frontend → Java: POST /api/clases/temas/12/presentacion con el PDF/PPTX.
  2. Java → Node: POST servicio-ia:3000/interno/procesar con el archivo en base64. Node responde 202 y trabaja en segundo plano.
  3. Node → IA externa: extrae el texto de cada diapositiva y pide las explicaciones (NVIDIA NIM o Gemini).
  4. Node → Java: PATCH servicio-clases:8080/interno/temas/12/estado → la clase pasa a BORRADOR.
  5. Frontend → Java: la profesora revisa y pulsa Publicar → Java → Node /interno/asignar.
  6. Node → Python: GET servicio-auth:8000/usuarios?rol=estudiante para saber a quién asignar.
  7. Node → Go: POST servicio-notificaciones:8080/interno/notificar por cada estudiante → campanita + correo.
  8. Java → LibreOffice (dentro del contenedor): si es PPTX lo convierte a PDF para el visor, sin bloquear la subida.
  9. Cuando un estudiante entrega, Node → Python busca a la profesora y Node → Go le avisa.
  10. Cuando la profesora crea un estudiante, Python → Java lo inscribe en su sección, Java → Node le asigna las preguntas de las clases ya publicadas y Python → Go le da la bienvenida.
  11. Cada vez que cambian las secciones o la lista de asistencia, Java calcula quién tiene acceso y se lo envía a Node.

Además los 4 servicios validan el mismo JWT (firmado con SECRET_KEY) sin tener que consultar al servicio de auth en cada petición.

10Login y claves encriptadas

bcrypt

La clave se guarda como hash con sal aleatoria. Ni la base de datos ni la profesora pueden leerla; solo se puede verificar.

JWT

Al iniciar sesión Python firma un token con id, nombre y rol, válido 12 horas. El frontend lo envía en Authorization: Bearer.

Roles

Solo la profesora crea usuarios, sube presentaciones y ve respuestas. Cada servicio verifica el rol del token.

def hash_password(password):
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()

# en la BD queda algo como:  $2b$12$Qd0r6r0Yb3m1Q8m5v2kF1eZ9...

11Inteligencia Artificial

Explicar diapositivas

Se extrae el texto de cada diapositiva (pdf-parse / lectura del XML del PPTX) y la IA redacta una explicación de 60–140 palabras por diapositiva.

5 preguntas distintas

La IA genera un banco de 5 × N preguntas, se eliminan duplicados y se reparten. Las ya usadas se guardan para no repetirlas con estudiantes nuevos.

Modo demo

Si no hay API key, el sistema sigue funcionando con explicaciones y preguntas por plantillas, para que siempre se pueda evaluar.

Visor de diapositivas

Java convierte el PPTX a PDF con LibreOffice (en segundo plano) y el navegador dibuja cada página con pdf.js junto a la explicación.

Pregúntale a la IA

El chat envía la pregunta con el texto y la explicación de la diapositiva actual y las últimas dudas del alumno, para que la respuesta tenga contexto.

Clases privadas

La lista de asistencia se guarda en Postgres (tabla clase_asistente, con @ElementCollection de JPA). Java se la envía a Node, que solo asigna preguntas y da acceso a los presentes.

Dudas para la profesora

Cada pregunta se guarda en MongoDB (colección consultas). La profesora las ve por alumno y sabe qué diapositivas generan más dudas.

El proveedor se elige en el .env con IA_PROVIDER: NVIDIA NIM (key gratuita en build.nvidia.com, API compatible con OpenAI) o Google Gemini. La profesora siempre puede corregir lo que escribió la IA antes de publicar.
